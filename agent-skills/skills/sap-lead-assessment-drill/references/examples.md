# Examples

## Weak answer pattern

“We should use AI and Kafka because they are modern and scalable.” This is weak because it starts with products, gives one system shape, hides ownership, and does not define evidence or a counter-metric.

## Stronger answer pattern

“The business needs faster exception handling without losing control. I would separate normal and high-risk cases. Normal cases can use deterministic rules and automated flow; high-risk cases keep explicit approval. Before choosing technology I would check current volumes, latency, error rate, ownership, and audit requirements. I would validate the design with a limited scope and track both cycle time and control exceptions.”

The second answer is stronger even without naming a specific SAP product because it frames the outcome, exposes the trade-off, separates conditions, allocates authority, asks for evidence, and proposes a bounded validation.
