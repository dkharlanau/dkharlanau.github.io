# Examples

## Strong case

A first-party implementation source names the process, deployed workflow, measured result, measurement period, and human control. Create or update the case with source facts, metric ownership, limitations, and supported graph IDs. Keep the state at `review_ready` until human approval.

## Duplicate case

A new article describes the same company, deployment, process, and product as an existing case but adds one metric. Propose an update to the existing case ID and attach the new source. Do not create a second implementation identity.

## Weak source

A vendor page says a feature *can* automate invoices but gives no customer deployment. Classify it as solution evidence or reject it as an implementation candidate. Do not create a measured business outcome.

## Missing metric

A source confirms production use but gives no KPI. Keep the implementation fact, set measurement as unknown, and add a proof gap. Do not estimate a result.
