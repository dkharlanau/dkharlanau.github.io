# Method

Start with identity and evidence, not with the desired story. Resolve whether the source describes a new implementation or an existing case before creating an ID. Map only supported concepts to canonical process, stage, pattern, technology, and platform IDs.

For every material statement, keep the evidence level explicit. `source_fact` is visible in the source. `supported_inference` is a reasoned conclusion. `runtime_proof` needs authorised observed runtime evidence. `unsupported_claim` must be removed or challenged. `proof_gap` stays visible for review.

A case is review-ready only when material claims have source ownership, broken IDs are resolved, limitations are stated, and no unsupported claim is presented as fact. Approval remains a human action.
