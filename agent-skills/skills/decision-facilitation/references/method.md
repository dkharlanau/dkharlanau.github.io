# Decision Facilitation Method

## Decision statement

A useful decision statement is narrow enough to choose between options. Examples:

- Choose the integration pattern for this business event.
- Decide whether the release can proceed under the current defect set.
- Decide where a business rule should be owned.

Avoid broad topics such as "integration strategy" or "AI approach" when the meeting needs one concrete choice.

## Constraint classes

Separate:

- legal or regulatory
- security or privacy
- contractual
- business policy
- architecture standard
- budget
- timing
- operational capacity
- technical limitation
- preference

Only verified non-negotiable constraints should remove options from the decision space.

## Option quality

Options should represent materially different ways to satisfy the outcome. Different vendors are not different options when they create the same architecture, authority model, and operating cost.

## Evidence labels

For important claims use:

- Evidence: observed or verified information.
- Assumption: believed true but not yet verified.
- Unknown: information not available.
- Decision: explicit choice made by an accountable owner.

## Deferment quality

A deferred decision is valid when it includes:

- exact missing evidence
- owner to obtain it
- test or source
- deadline or event trigger
- next decision point

"Need more analysis" is not a decision plan.

## Trade-off rule

For each option state both sides. A good option is rarely best on every dimension. If all options appear to have only benefits, the analysis is probably hiding costs or using vague criteria.
