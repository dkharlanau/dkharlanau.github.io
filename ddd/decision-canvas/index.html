Decision Canvas.

Use this canvas for one material business decision. Start with truth and invariants. Then describe judgment, authority, the real commitment, evidence, and learning. The output is JSON that follows the framework decision schema.

Why this exists

Do not design an agent. Design one decision first.

A useful decision model should still make sense if the actor later changes from a person to deterministic software, an AI model, or a mix of all three.

decision.schema.json SAP examples framework.json
01

Scope the decision.

Name the business outcome and the semantic context before choosing technology.

Use a stable machine-friendly id. If empty, it is generated from the outcome.
02

Separate truth from context.

One line per item. A retrieved document and a current SAP object are not the same kind of evidence.

03

Bound the judgment.

Be explicit about what interpretation is useful and what must stay outside probabilistic behavior.

04

Check decision economics.

The canvas uses these factors only to suggest a design posture. It does not produce a fake scientific score.

05

Shape the authority envelope.

Autonomy is not a personality setting. Attach it to this action and define its limits.

06

Name the commitment.

This is the point where analysis becomes a promise, transaction, reservation, approval, or durable state change.

07

Keep the operating trail.

Evidence should make the decision reviewable without turning every trace into permanent business truth.

08

Define the learning boundary.

Production evidence may propose a change. It should not quietly promote itself into policy.
