<p class="eyebrow">Outcome and scope tool</p><h1>Impact Mapping</h1>
<p class="lead">Use Impact Mapping when a team is already discussing features but has not shown how those features change behavior and move a measurable business goal.</p>

<section><h2>The chain</h2>
<table class="study-table"><thead><tr><th>Level</th><th>Question</th></tr></thead><tbody>
<tr><td>Goal</td><td>What measurable result are we trying to improve?</td></tr>
<tr><td>Actor</td><td>Who can help or prevent the goal?</td></tr>
<tr><td>Impact</td><td>What behavior must change?</td></tr>
<tr><td>Deliverable</td><td>What could we change or build to enable that behavior?</td></tr>
</tbody></table>
</section>

<section><h2>Working method</h2>
<ol>
<li>Write one measurable goal with a time horizon.</li>
<li>List actors who can materially influence it.</li>
<li>For each actor, describe observable behavior changes that would help or hurt the goal.</li>
<li>Only then brainstorm deliverables.</li>
<li>Mark assumptions between deliverable → impact → goal.</li>
<li>Prefer experiments or thin slices when evidence is weak.</li>
</ol></section>

<section><h2>SAP example</h2><p>Goal: reduce order-release delay from 8 hours to 2 hours. Actor: credit analyst. Desired impact: resolve standard credit blocks without waiting for manual data collection. Deliverables might include a better worklist, missing-data checks, workflow changes, or an automated evidence summary. The map prevents “build a new Fiori app” from becoming the goal itself.</p></section>

<section><h2>Decision rules</h2><ul>
<li>If the goal has no measure, improve the goal before prioritizing deliverables.</li>
<li>If an impact is actually a feature, rewrite it as a behavior change.</li>
<li>If several deliverables support the same impact, compare them as options instead of treating all as scope.</li>
<li>If there is no evidence that the impact changes the goal, design an experiment or measurement step.</li>
</ul></section>
