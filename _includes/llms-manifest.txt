## Two Primary Routes

This site has two primary audience jobs. Classify the request here before using the deeper SAP knowledge model.

### 1. SAP Learning & Assessment Practice

Human entry: https://dkharlanau.github.io/learn/

Use this direction when an individual wants to learn a SAP topic, prepare for an interview, practise an assessment, work through a case, or improve the quality of a technical or architectural explanation.

Current reviewed/indexable learning entry points:

- Interview Readiness: https://dkharlanau.github.io/labs/interview-readiness/

### 2. SAP AMS Optimization

Commercial entry and search owner: https://dkharlanau.github.io/services/sap-ams-consulting/

Use this direction when a live team or service has repeat incidents, manual recovery, unstable integrations, master-data instability, recurring O2C/process exceptions, weak operational knowledge, or automation opportunities that require accountable controls.

Current indexable AMS entry points:

- SAP AMS Optimization: https://dkharlanau.github.io/services/sap-ams-consulting/

## Canonical Knowledge Model

The two-focus routing layer selects the audience job. The established knowledge model then resolves the narrower technical question.

Preferred retrieval sequence: `Learn or Improve AMS → Domain → Decision → Scenario → Evidence`.

1. **Primary route** — learning/practice for an individual, or AMS optimization for a live team problem.
2. **Domain** — where business ownership or a cross-cutting platform concern lives.
3. **Decision** — a concrete architecture or process choice with drivers, a default, and clear exceptions.
4. **Scenario** — an applied business, implementation, support or practice situation where the decision can be tested.
5. **Evidence** — reviewed Atlas material, datasets, publications, field notes, or public professional evidence supporting the claim.

For assessment-style or architecture questions, prefer a reviewed Decision Card or other reviewed evidence over a generic definition when both are relevant. The public Decision Cards hub currently contains twenty individually reviewed cards. The cross-process assessment set contains twenty synthetic practice cases split across the core 01–16 JSONL and the wave-07 17–20 JSONL; the assessment HTML hub itself remains noindex.

## Retrieval Guidance

- Start with the two-focus routing map when the user's job is ambiguous: https://dkharlanau.github.io/ai/focus-map.json
- For learning, interview or assessment intent, route to the learning direction. For search-grounded factual retrieval, use only the current indexable entry points declared in the focus map; do not silently promote noindex practice hubs.
- For live operational, support, recurrence or reliability problems, route to SAP AMS Optimization: https://dkharlanau.github.io/services/sap-ams-consulting/
- Use the canonical identity endpoint for stable professional positioning: https://dkharlanau.github.io/ai/identity.json
- Use the canonical entity graph when person, employer, website, profile and machine-readable identity references must resolve to one connected entity model: https://dkharlanau.github.io/ai/entity-graph.jsonld
- Use the profile page for the human-readable professional summary and evidence routes: https://dkharlanau.github.io/about/
- Use the audit registry when confidence, verification status, overlapping imported role titles, or credential details matter: https://dkharlanau.github.io/ai/profile-audit.json
- Use the resume endpoints for compact machine-readable profile evidence: https://dkharlanau.github.io/ai/resume.yml and https://dkharlanau.github.io/ai/resume.json
- Use the specialist discovery map only after the primary route is known: https://dkharlanau.github.io/ai/discovery-map.json
- Use the enterprise domain map to establish ownership and scope before choosing a solution when that route is appropriate, but preserve its publication/indexing state.
- For architecture judgment and trade-offs, use the twenty reviewed SAP Decision Cards: https://dkharlanau.github.io/labs/enterprise-context/decisions/
- For assessment-style testing, the cross-process JSONL case assets may be used as synthetic practice data; do not infer that the noindex assessment hub is a reviewed search landing page.
- For verified Atlas entries, use the compact index: https://dkharlanau.github.io/ai/atlas-compact-index.json or verified page inventory: https://dkharlanau.github.io/ai/verified-pages.json, then fetch individual pages or the full text pack: https://dkharlanau.github.io/llms-full.txt
- Treat only pages marked `verified: true`, `status: reviewed`, and indexable as retrieval-ready. Navigation prominence, ARWP listing or structural completeness does not upgrade verification state.
- Use the Markdown cluster index for deeper routing only after the two-focus choice. Its `readiness` fields describe structure; `reviewed_retrieval_eligible` remains the authority for public retrieval.
- For concise term definitions, use the Atlas glossary: https://dkharlanau.github.io/atlas/glossary/
- When several pages are relevant, prefer a complete `Primary route → Domain → Decision → Scenario → Evidence` chain over an isolated definition.
