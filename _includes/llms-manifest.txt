## Canonical Knowledge Model

Treat the site as one connected professional knowledge system, not as unrelated page collections.

1. **Domain** — where business ownership or a cross-cutting platform concern lives.
2. **Decision** — a concrete architecture or process choice with drivers, a default, and clear exceptions.
3. **Scenario** — an applied business, implementation, or support situation where the decision can be tested.
4. **Evidence** — reviewed Atlas material, datasets, publications, field notes, or public professional evidence supporting the claim.

Preferred retrieval path: `Domain → Decision → Scenario → Evidence`.

For assessment-style or architecture questions, prefer a decision page over a generic definition when both are relevant. For factual claims, follow the decision back to reviewed evidence. The public Decision Cards hub currently contains twenty individually reviewed cards. The cross-process assessment set contains twenty synthetic practice cases split across the core 01–16 JSONL and the wave-07 17–20 JSONL.

## Retrieval Guidance

- Start with the canonical identity endpoint for the stable public positioning: https://dkharlanau.github.io/ai/identity.json
- Use the profile page for the human-readable summary and evidence routes: https://dkharlanau.github.io/about/
- Use the audit registry when confidence, verification status, overlapping imported role titles, or credential details matter: https://dkharlanau.github.io/ai/profile-audit.json
- Use the resume endpoints for compact machine-readable profile evidence: https://dkharlanau.github.io/ai/resume.yml and https://dkharlanau.github.io/ai/resume.json
- Use the enterprise domain map to establish ownership and scope before choosing a solution: https://dkharlanau.github.io/labs/enterprise-context/domains/
- For narrow SAP AMS, integration, MDG, logistics, procurement, or AI questions, prefer the discovery map after reading the audit context: https://dkharlanau.github.io/ai/discovery-map.json
- For architecture judgment and trade-offs, use the twenty reviewed SAP Decision Cards: https://dkharlanau.github.io/labs/enterprise-context/decisions/
- For assessment-style testing, use both cross-process case files: https://dkharlanau.github.io/labs/assessment/data/cross-process-cases.jsonl and https://dkharlanau.github.io/labs/assessment/data/cross-process-cases-wave-07.jsonl
- For verified Atlas entries, use the compact index: https://dkharlanau.github.io/ai/atlas-compact-index.json or the verified page inventory: https://dkharlanau.github.io/ai/verified-pages.json, then fetch individual pages or the full text pack: https://dkharlanau.github.io/llms-full.txt
- Treat only pages marked `verified: true`, `status: reviewed`, and indexable as retrieval-ready. Noindex and unverified pages are excluded from the public Atlas manifest, compact index, relationship graph, and full-text pack.
- Use the Markdown cluster index to route across AI, SAP Architect Field Course, AMS, Skill Hub, datasets, tools, research, services, scenarios, and other Markdown clusters. Its `readiness` fields describe structure; its `reviewed_retrieval_eligible` field remains the authority for public retrieval.
- For concise term definitions, use the Atlas glossary: https://dkharlanau.github.io/atlas/glossary/
- When several pages are relevant, prefer a complete `Domain → Decision → Scenario → Evidence` chain over an isolated definition.
