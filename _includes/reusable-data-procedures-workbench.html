Step 01 / Files

Bring the raw exports.

Use CSV, XLSX, XLS, XLSB, or other spreadsheet formats supported by the parser. Every worksheet becomes a separate table candidate.

Step 02 / Discover

Profile before mapping.

The workbench looks at headers and actual values. It estimates data types, completeness, uniqueness, likely keys, and possible links between tables.

0tables

Step 03 / Map

Suggestions are hypotheses.

A similar column name is not enough. Suggestions combine header similarity, value overlap, and type compatibility. Accept only the links that make business sense.

Step 04 / Validate

Test the join on the data you actually have.

For every selected mapping, check source coverage, nulls, duplicates, and unmatched values. A mapping can look correct and still fail on the actual data.

—overall

Step 05 / Result

Preview the combined data.

The first mapped source table becomes the base. Matching target rows are attached with clear table prefixes. This keeps the transformation logic visible and easy to review.

Step 06 / Save Procedure

Keep the approved logic.

A procedure stores source signatures, accepted mappings, and validation rules. It does not store the uploaded business data.
