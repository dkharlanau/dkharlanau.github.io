12 / Run and change

Operate the whole solution, including its failure paths

A working development URL is not a production operating model. Define service ownership, support hours, monitoring, release controls and recovery before go-live. The platform can provide mechanisms; the project must choose and test the complete path.

Cloud ALM, Focused Run and Solution Manager

Cloud ALM supports implementation and operations for supported SAP cloud and hybrid scenarios. Focused Run serves advanced, high-volume monitoring needs. Solution Manager is an established ALM platform with a lifecycle transition to consider. SAP’s published mainstream-maintenance horizon for Solution Manager 7.2 is 2027; check the applicable maintenance and transition scope rather than starting a new design from an old monitoring diagram.

For every tool, list the actual covered systems and collected signals. “Central monitoring” is not proof that all interface fragments, partner systems and business documents are correlated.

Release checklist: one change through the landscape

Version the code and interface/schema changes. Build a reproducible artifact using a dependency lock file. Run unit, contract, negative authorization and integration tests. Promote the same reviewed artifact with environment-specific configuration outside source code. Validate trust, destination, role assignment and data migration in the target. Record release approval and the rollback/compensation decision.

Rolling back application code does not reverse an ERP posting, a sent email or an external order. A schema downgrade may also be unsafe after new data has been written. Define a business compensation or forward-recovery path, not only a deployment rollback button.

Define RTO (target time to restore service) and RPO (acceptable data-loss window) for the business need. Test backup restoration, replay, reconciliation and a manual fallback. Redundancy is not the same as a tested disaster-recovery procedure.

Scale the safe path, not the failure loop

Original operating example: an ERP endpoint accepts 5 requests/second while 12 arrive each second. An unlimited queue postpones the incident; it does not solve it. Limit concurrency, apply backpressure and agree queue capacity and maximum business delay. If the endpoint fails, use bounded retries with backoff and only retry-safe operations. A circuit breaker temporarily stops calls to an unhealthy dependency; it does not resolve already ambiguous writes.

Monitor traffic, latency, errors, saturation and the age of unfinished business work. A low error rate with a growing queue may still violate the process objective. Alert on the owner-relevant symptom: “approved supplier reviews not confirmed in ERP”, not only “worker process alive”.

High availability is not a complete recovery design

Check the failure domain: app instance, availability zone, data store, identity provider, external API or region. Restore data and configuration: destinations, trust, role assignments, service instances, deployment descriptors and secrets references. The customer must maintain the required configuration backups and recovery instructions.

SAP documentation check: the current multi-region CAP example has defined prerequisites, paired subaccounts, service entitlements and a single-tenant scope. It is not a promise that any BTP service or multitenant app fails over automatically. Check supported services, region pairs and feature status. A database replica alone does not restore the UI route, integration identity, queue processing or ERP connection.

Documentation and further reading: resilience, queue, configuration-backups, multi-region.

Evidence rule: technical telemetry explains execution; audit evidence explains security-relevant actions; the owning business application confirms the transaction; an agreed KPI measures value. Use all four where the risk requires them.

Reference: operations, cloud-alm, logging, audit, retention.

A scheduled job is green but supplier status did not change. What do you inspect next?

Trace the job’s request to the application, interface and ERP response. Confirm the official business state and any rejected validation/authorization. The scheduler can only establish the status of its own execution contract.
