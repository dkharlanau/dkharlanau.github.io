11 / Govern

Make ownership and control part of execution

Imagine that a supplier changes its quantity unit from “device” to “case of ten”. An agent orders 1,200 cases while believing it has ordered 1,200 devices. The API succeeds; 12,000 devices are committed. This is not mainly a prompt problem. The unit contract, validation, purchasing limit and approval control failed.

Governance must be enforced where an action becomes real. Recording a policy in a document or an agent registry is useful, but a bypassable policy does not protect the ERP posting.

SAP AI Agent Hub / LeanIX supports inventory and governance in the wider architecture context. Discovery and observation depend on integrations and supported assets; do not assume every unregistered custom agent is discovered automatically. Runtime and gateway controls enforce supported paths. Identity services establish relevant identities and provisioning. Cloud ALM and native tools support operations; Signavio can analyze supported process/agent traces and business value.

The business owner defines approval authority and acceptable risk. The solution architect defines boundaries and failure handling. Security owners review identity and data controls. Operations owns detection and recovery. None of these responsibilities disappears because the runtime is SAP-managed.

The safeguards for the wrong-quantity scenario

Validate the contract version and unit conversion. Compare the resulting base quantity with demand, stock coverage, contract limits and storage capacity. Calculate total value in an explicit currency. Escalate material deviations. Do not let a payment agent treat the existence of a purchase order as sufficient evidence for payment; the applicable invoice, receipt and payment controls still apply.

Keep the initiating identity, approval, request ID, contract/model version and resulting ERP document reference in the right evidence stores. A controlled stop must disable the risky action, preserve work and provide a manual route. Shutting down all replenishment without understanding queued work can create a second incident.

Measure the process, not the performance of a chatbot

For the supplier-review case, useful outcomes are review lead time, reopened/rejected cases, unauthorized-action attempts, incomplete ERP updates and cost per completed review. Define how each measure is calculated and compare against a baseline. A low API latency does not prove faster approved onboarding.

An agent is marked “verified” in the registry. Can it call any approved API?

No. Verification is one governance record. The particular agent identity must be authorized for the tool, object, operation and business scope, and any required approval must still exist. Test the enforcement path and possible bypasses.
