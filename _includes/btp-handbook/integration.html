Design the business contract, then the transport

An integration is a promise between systems. It specifies what a message means, who owns it, when it should arrive and what happens when delivery or processing is uncertain. An adapter is only one part of that promise.

Message mapping maps structures and fields. Value mapping translates values such as external unit or organization codes. A syntactically valid mapping can still be commercially wrong: “case” and “piece” may both be strings, but they do not represent the same quantity.

In Integration Advisor, a MIG defines an implementation-specific message structure and constraints. A MAG defines the mapping between source and target structures. Runtime artifacts can support the chosen integration; they do not remove the need to agree business meaning.

Event-driven does not mean “fire and forget the business”

A producer publishes a fact. A broker routes it to consumers, often through queues. A consumer performs its own action. The producer does not need to name every consumer, but the enterprise still needs an owner for the complete outcome.

A topic identifies/routes a category of messages; a queue holds messages for consumption under its configured behavior. Broker delivery, retention and ordering are bounded by the selected product, protocol and configuration. SAP Event Mesh service offerings, Integration Suite Event Mesh capability and advanced event mesh are not names to collapse into one universal license or feature set. Check the exact offer and any migration guidance.

Best Effort, Exactly Once and Exactly Once In Order describe particular messaging contracts. They are not universal synonyms for synchronous or asynchronous communication. End-to-end business effects require their own design: a receiver may commit a document before its response is lost.

Use a stable business/request key, an idempotent receiver or a deduplication record, bounded retries, a dead-letter or equivalent error path, correlation and reconciliation. A transactional outbox can connect a local database change to eventual event publication; it does not create one atomic transaction across independent ERP and cloud systems.

Choose a real ERP API in SAP Business Accelerator Hub only after checking edition, release, supported operation, communication scenario, authentication, required fields and limitations. For relevant S/4HANA Cloud integrations, the communication user/system/arrangement must be configured. An API listed in a catalog is not necessarily enabled in the customer tenant.

AIF and middleware operate at different boundaries

SAP Application Interface Framework can support business-oriented monitoring and correction of suitable backend interfaces. Cloud Integration handles its own messages and technical processing. A business user’s need to correct an error may justify AIF in a supported scenario; it does not make AIF mandatory for every interface.

For PI/PO modernization, inventory first: retire unused interfaces, identify standard content, assess gaps, migrate or redesign, and test both normal and failure paths. A pipeline approach is a reusable integration architecture, not simply all interfaces combined into a single giant iFlow.

The ERP call timed out. Why is “send the same POST again” an unsafe default?

The ERP may have committed the change before the response was lost. First reconcile using a supported business reference or status lookup. Retry only with the interface’s defined idempotency behavior. Without a safe lookup/contract, route the unknown outcome for controlled recovery.
