18 / Evidence and limitations

What supports the guide—and what still needs verification

This is an independent personal study handbook, not an SAP publication, commercial offer or certification guarantee. It is based on the supplied SAP Learning extracts and selected public primary documentation. The synthetic supplier-review case, diagrams, code, questions and design judgments are original teaching examples.

Evidence levels: the course explains concepts and methodology; product documentation constrains a real implementation; a local test proves only the behavior it executes. Announcements describe direction and released or planned capabilities, not universal tenant availability. Product names, plans, regional availability and certification formats require a current check.

Important qualifications added during the rewrite

Simplified claim to avoidWhat the guide teaches instead
“Free tier starts charging automatically when the limit is exceeded.”Check each plan. Moving to paid capacity can require an explicit plan change or different provisioning.
“Every foundation service comes with the platform account.”A service still needs the appropriate entitlement, plan, region and technical configuration.
“Cloud Foundry supports Python, so CAP is a Python model.”Runtime language options and programming-model support are different questions. CAP’s main runtimes are Node.js and Java.
“SAP-managed means no customer operating responsibilities.”SAP manages defined platform layers; customers still own application behavior, access, data, configuration and business recovery.
“A data fabric or knowledge graph eliminates hallucinations.”Grounding helps only with valid, current and permitted evidence. Models and actions still require validation.
“EO means asynchronous; a completed message means one correct transaction.”Delivery mode, messaging quality and business idempotency are separate design dimensions.
“SSO means the user may approve; offboarding revokes everything instantly.”Application/backend authorization and token/session/provisioning lifecycle must be handled explicitly.
“Registering an agent secures every tool call.”Verify identity, policies and enforcement on the actual runtime, gateway and backend path.
“Data Retention Manager deletes every ERP or SaaS record.”Its documented BTP application scope does not replace the source applications’ supported retention mechanisms.
“One page replaces hands-on experience.”Use reading to explain, the exercises to reason, and real system tests to verify. Keep those evidence levels separate.
