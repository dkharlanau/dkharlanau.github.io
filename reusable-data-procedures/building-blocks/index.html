Detail / Composition

Do not copy a good rule into twenty procedures.

Some logic belongs to one procedure. Other logic is a reusable capability: find an Excel table, normalize a SAP identifier, parse a German decimal, assert many-to-one cardinality, or route invalid rows. Those capabilities should become versioned blocks.

Reuse ladder

Reuse at the right level.

L1Primitive

A small deterministic operation such as trim, cast, compare or hash.

L2Block

A typed reusable capability with parameters, tests and a version.

L3Pattern

A recommended arrangement of blocks for a common data problem.

L4Procedure

An end-to-end business task with explicit source and output contracts.

L5Pack

A curated domain bundle with procedures, blocks, references, fixtures and guidance.

Block contract

A reusable block needs more than a function name.

{
  "id": "sap.normalize-material-id",
  "version": "2.1.0",
  "family": "cleaner",
  "input": {"type": "string"},
  "output": {"type": "string"},
  "parameters": {"length": 18, "preserveRaw": true},
  "properties": ["deterministic", "idempotent"],
  "tests": ["already-normalized", "leading-zeros", "null", "invalid-length"],
  "owner": "data-platform",
  "risk": "medium"
}

Composition rules

Make the graph explainable.

Pin versions

An approved procedure references a specific compatible block version. “Latest” is convenient until latest changes on Friday afternoon.

Prefer pure blocks

A block should normally transform input to output without hidden filesystem, network or global-state effects.

Declare side effects

If a block writes a file, calls an API or reads reference data, this belongs in its contract.

Test properties

For cleaners, idempotence is valuable. For joins, cardinality invariants matter. Test the property, not only three sample values.

Keep custom code visible

Custom Python is allowed as an escape hatch, but it gets an owner, tests, risk classification and dependency review.

Promote repeated logic

If the same implementation appears in three procedures, review whether it should become a block. Not every two-line expression deserves a tiny kingdom.

Patterns

Capture proven arrangements, not only atoms.

Lookup enrichment

Locate → canonicalize key → assert target uniqueness → join → coverage validation → route unmatched rows.

Workbook extraction

Inspect workbook → score candidate sheet → locate header → detect region → remove repeated headers → preserve coordinates.

Monthly reconciliation

Resolve current inputs → normalize IDs → aggregate controls → compare → classify differences → publish result and evidence.

Migration quality gate

Schema contract → mandatory fields → domains → references → duplicates → reconciliation → blocking decision.
