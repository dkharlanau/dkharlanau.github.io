Roadmap

Prove the contracts before building the platform.

The main risk is not choosing the wrong web framework. It is mixing procedure logic, deployment settings and run history until no one can tell what changed. Development should prove the object model and ugly cases first.

OverviewFrameworkCatalogDeployment & RunTestingRoadmap

Phase 0

Stabilize the language and boundaries.

Contracts

Procedure + Deployment + Run

Define what belongs to reusable business logic, operating configuration and execution evidence.

Catalog

Asset vocabulary

Primitive, block, pattern, procedure, pack, reference dataset, deployment and run all get clear identities and relations.

Cases

Real problem library

Collect 10–20 repeated cases from SAP exports, reconciliation, master data, migration and operational reporting.

Exit

No hidden category errors

A schedule change is not a procedure change. A run failure is not a catalog status. The model makes these differences explicit.

Phase 1

Build the test corpus before the clever discovery engine.

Golden

Expected results

Small synthetic source bundles with expected outputs, exceptions, validations and locator decisions.

Drift

Mutation library

Move headers, rename sheets, change locale, duplicate keys and insert footers to test recovery and blocking behavior.

Replay

Historical evidence

Where policy allows, replay approved old run packages to compare procedure and engine versions.

Exit

Release confidence

The framework can show which assumptions are protected by tests instead of merely claiming that a procedure is reusable.

Phase 2

Make deterministic local execution boring.

Core

Python engine

Procedure parser, source resolver, locator, transform compiler, validation engine and atomic output writer.

Interface

CLI

inspect, validate-procedure, run, compare-run, explain-run and test.

Evidence

Run contract

Input hashes, resolved dependencies, plan hash, drift, validations, exceptions and output hashes.

Exit

Repeatability

The same inputs, pinned dependencies and procedure version produce the same business result.

Phase 3

Add discovery, catalog and composition.

Discovery

Structure and mapping evidence

Workbook inspection, source-role matching, key candidates, mapping evidence and drift classification.

Catalog

Search by capability

Find procedures and blocks by domain, task, source family, owner, trust, policy and dependencies.

Composition

Shared blocks and packs

Promote stable locators, cleaners, parsers and validators into versioned reusable assets.

Exit

Reuse before invention

New work starts by searching existing capabilities and patterns instead of creating another private script.

Phase 4

Add deployments and unattended operation.

Trigger

Manual, schedule, inbox, API, event

All triggers create the same run request and pass through the same gates.

Safety

Idempotency and concurrency

Prevent duplicate publication, define queue or overlap policy, and separate retryable infrastructure failures from business failures.

Policy

Deployment profiles

Local-safe, team-standard, production-critical and restricted-data profiles reuse known control bundles.

Exit

Unattended but explainable

Scheduled execution can run safely without hiding why it published, stopped or requested review.

Phase 5

Build the shared service and governance layer.

Service

Registry + run API

Procedures, deployments, run requests, evidence, reviews and dependency queries become stable resources.

Operations

Observability

Run duration, queue time, input size, drift rate, exception trend, failure category, publication status and consumer lineage.

Governance

Promotion and rollback

Policy profiles, review freshness, impact analysis, deprecation and rollback operate on explicit assets.

Exit

Supportable service

The framework can be operated by a team instead of depending on the consultant who remembers where the clever part lives.

Phase 6

Use AI where uncertainty remains.

Semantic

Explain unfamiliar structures

Use metadata, dictionaries and approved samples to suggest source roles, aliases and field meaning.

Retrieval

Find similar assets first

Search approved procedures, blocks, mappings and test cases before proposing new logic.

Assist

Suggest repairs and tests

Propose drift repair, validation rules and mutation cases with visible evidence.

Boundary

No hidden execution

Accepted suggestions become explicit contracts, blocks or procedure revisions. Production runs stay deterministic.

Evaluation

Measure whether the framework removes work without removing control.

MetricQuestion
