Reference case 01 / SAP Sales

Sales Order Material Reconciliation.

The business task is simple to say: take a monthly Sales order export and make sure every material can be resolved to the controlled material value used by the downstream process. The interesting part is everything that can move around that sentence.

CasebookSAP Logistics PackReviewDecision Memory

Business question

Can every Sales order item be connected to one trusted material?

Primary source

A synthetic SAP Sales workbook with Sales Document, Item, Material, Plant, Order Quantity and Unit.

Reference source

A controlled alias dataset that maps source material values to the canonical material used by the downstream consumer.

Key

Sales Document + Item must stay unique in the order source. The material alias key must also stay unique.

Publication rule

Publish only when all required materials resolve, key cardinality is safe and control totals remain stable.

Run 01 / golden

The first run is intentionally boring.

The table is on sheet Orders, header row 8. Four order items are present and all four material values resolve through sap.material-aliases@2026.08.1.

SignalExpected result
LocatorHeader-anchor locator finds row 8 with high confidence.
Sales keySales Document + Item is unique: 4 keys from 4 rows.
Reference keySource material is unique in the alias dataset.
Coverage4 / 4 materials resolved, 100% coverage.
Quantity control27 source units remain 27 result units.
DecisionPublish result and zero exceptions.

Run 02 / drift

The task is the same. The file is not.

Table moved

The order table starts at row 11 instead of row 8. This is structural drift, not business drift.

Headers changed

Material becomes Material Number and Item becomes Item No.. Approved aliases allow the locator to recover.

New value

A new source material EXT-Q9 appears. It has no row in the pinned reference release.

Safe outcome

The procedure does not invent a material mapping. It creates a blocking reference-gap review item and withholds publication.

Classification: table movement and header aliases are compatible/resolvable drift. The unknown material is a business data gap and requires a decision.

Human loop

One question, one scoped decision.

1. Review item

“Should source material EXT-Q9 map to canonical material MAT-471103 for this Sales export family?” Evidence includes the unresolved value, source lineage and the candidate supplied by an approved business reference.

2. Decision

The mapping is approved for the defined Sales export source family. The decision is not global and does not redefine the meaning of sap.material-id.

3. Reference release

A new reference release sap.material-aliases@2026.08.2 adds the approved row. The old release remains available for replay.

4. Procedure revision

The procedure is revised from 0.1.0 to 0.1.1 only to pin the newly approved reference version. Business transformation logic stays unchanged.

5. Replay

The same Run 02 source is executed again. All four rows resolve, the quantity control stays stable and publication can proceed.

What this case proves

The framework has to distinguish movement from meaning.

Coordinates are evidence, not identity

Moving the table does not create a new procedure version because the locator is semantic.

Aliases are not business mappings

Renaming Material to Material Number is a header alias. Mapping EXT-Q9 to a canonical material is a business decision.

Reference data changes are traceable

The new mapping gets a released version and an explicit decision record.

Safe failure is part of success

The correct Run 02 result before review is withhold, not a guessed output.

Replay needs pinned evidence

Run records show the exact procedure and reference versions used before and after the decision.

Learning stays deterministic

A human decision changes a versioned asset. Future execution still follows explicit contracts.
