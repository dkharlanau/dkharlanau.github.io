Reference case 02 / SAP Procurement

Purchase Order Material Reconciliation.

The task looks close to the Sales case, but Procurement adds a useful complication: a supplier material code only has meaning together with its supplier. The case checks whether the framework can reuse the same control model without pretending the business semantics are identical.

CasebookSAP Logistics PackReviewDecision Memory

Business question

Does each PO item agree with one controlled supplier-material relationship?

Primary source

A synthetic SAP Procurement workbook with Purchasing Document, Item, Supplier, Material, Supplier Material, Plant, quantity, unit, price and currency.

Reference source

A controlled cross-reference maps Supplier + Supplier Material to one canonical SAP Material.

Key

Purchasing Document + Item identifies the PO row. The reference key is composite because the same supplier material text may mean something different for another supplier.

Publication rule

Publish only when every composite key resolves, the mapping agrees with the SAP Material, item identity is unique and quantity controls remain stable.

Run 01 / golden

The controlled path proves the basic contract.

Four PO items resolve through sap.supplier-material-cross-reference@2026.08.1. Purchasing Document + Item is unique, all mappings agree with the SAP Material and the ordered quantity stays 72.

Run 02 / drift

Structural drift is recoverable. A new supplier mapping is not.

Table moved

The table starts at row 11 instead of row 7 and the sheet changes from Purchase Orders to PO Export.

Headers changed

Purchasing Document becomes Purchase Order, Item becomes PO Item, and other approved aliases appear.

New supplier code

Supplier SUP-2000 sends VEND-Q9. The same PO row contains SAP Material MAT-471103, which is strong evidence but not an approved mapping.

Safe outcome

Coverage falls to 75%. The result is withheld and a mapping review is created. The procedure does not write into reference data by itself.

Important: observing VEND-Q9 next to MAT-471103 is enough to propose a candidate. It is not enough to silently change a controlled cross-reference.

Why the key matters

Supplier Material is not a global identifier.

Unsafe shortcut

Using only Supplier Material as the reference key assumes every supplier uses a globally unique code space.

Controlled model

The key is Supplier + Supplier Material. Another supplier may use the same text for another material without creating a conflict.

Cardinality gate

One composite key must not point to two canonical materials in the same valid reference release.

Semantic boundary

The supplier code stays a source-specific identifier. The mapped target represents sap.material-id.

Human loop

Evidence becomes a scoped reference change.

1. Review item

Ask whether SUP-2000 + VEND-Q9 should map to MAT-471103 for this Procurement source family.

2. Decision

The mapping is approved with composite supplier scope. It does not turn VEND-Q9 into a global Material ID.

3. Reference release

sap.supplier-material-cross-reference@2026.08.2 adds the approved row while the previous release stays available for replay.

4. Procedure revision

Procedure 0.1.1 pins the approved reference release. Transform and validation logic remain unchanged.

5. Replay

The same Run 02 source now resolves all four rows, mapping coverage returns to 100% and publication proceeds.

What this case proves

The reusable part is the control model, not identical business logic.

Shared pattern

Both Sales and Procurement use locate, normalize, lookup, validate, review, version and replay.

Different meaning

Sales used a direct material alias. Procurement needs a supplier-scoped composite cross-reference.

Same-row evidence is still evidence

A PO Material can support a mapping suggestion without granting permission to change reference data.

Composite keys deserve tests

Reference cardinality must be tested on the real business key, not on whichever column is easiest to index.

Item IDs stay strings

00010 must not silently become 10. Once significant representation is lost, the framework must not invent it back.

Safe failure is explainable

Run 02 is a controlled review state, not an infrastructure failure.
