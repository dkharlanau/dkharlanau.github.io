Architecture & libraries

Separate discovery, execution and control.

The architecture should allow experimental matching and AI assistance without making execution unpredictable. The runtime executes an approved procedure; the catalog makes assets discoverable; governance controls what may be promoted and reused.

OverviewCatalogBlocksGovernanceProcedure ModelArchitecture

Logical layers

One platform, replaceable responsibilities.

Source adapters

Read Excel, CSV, Parquet and later enterprise sources. Convert them into a common tabular representation while keeping source metadata.

Profiler + locator

Build structural fingerprints and find the intended data region using tables, names, anchors, scoring and controlled fallbacks.

Discovery engine

Generate candidate keys, mappings, aliases and source-role matches. Combine deterministic signals with optional semantic or AI signals.

Procedure compiler

Turn approved choices, source contracts and reusable block references into a deterministic execution graph.

Execution engine

Apply cleanup, joins, filters, conversions, derived fields, aggregations and exception routing without depending on an LLM.

Validation engine

Run structural, relational, reconciliation and business checks. Produce machine-readable evidence and publication decisions.

Catalog & registry

Index procedures, blocks, patterns, packs and reference datasets by stable ID, domain, task, owner, trust, lifecycle and policy metadata.

Dependency graph

Track which procedures use shared blocks or reference data and which consumers depend on their outputs. Use it for impact analysis and deprecation.

Governance & policy

Control lifecycle, promotion, review freshness, allowed environments, network access, AI data modes and higher-risk changes.

Provenance & run evidence

Keep versions, approvals, source hashes, drift, validations, exceptions and output hashes separate from catalog metadata.

Interfaces

CLI first, then API and UI. Agents become clients of the same catalog and execution service instead of receiving a private hidden path.

Candidate stack

Choose libraries by responsibility.

This is a working shortlist, not a dependency lock file. Keep adapters thin enough to replace a library when requirements change.

Polars

Strong candidate for the main Python dataframe runtime, especially for columnar operations and lazy execution. Useful when a procedure should compile into an optimized transformation plan.

DuckDB

Good embedded SQL engine for joins, aggregations, CSV/Parquet work and analytical steps. It also gives a future browser option through DuckDB-Wasm, with browser memory and threading limits to respect.

Apache Arrow / PyArrow

Useful common in-memory and interchange layer. Parquet is a good internal artifact format for larger intermediate data and test fixtures.

openpyxl

Python adapter when workbook-level XLSX details matter. Keep it at the boundary; the core procedure model should not depend on Excel cell objects.

SheetJS CE

Candidate for a future browser client that needs local spreadsheet reading or preview. It is a UI/input adapter, not the procedure engine.

RapidFuzz

Useful for field-name similarity and alias matching. Treat fuzzy text similarity as one mapping signal, never as proof of semantic equality.

Pandera

Good fit for code-centric dataframe schema checks close to the Python runtime. It can represent typed contracts and collect multiple validation errors.

Great Expectations

Consider when validation becomes a larger governed capability with reusable suites, persisted validation results and human-readable data-quality evidence.

Pydantic + JSON Schema

Use for procedure, block and run-report contracts, API validation and migrations between spec versions. JSON Schema keeps contracts portable outside Python.

FastAPI

A reasonable service boundary later: catalog entries, procedures, discovery sessions, runs and reports become explicit API resources while the engine stays a normal Python package.

AI layer

Make semantic help a plug-in.

Metadata-only mode

Send column names, types, descriptions and statistics without row values. Useful when data sensitivity is high.

Masked sample mode

Use carefully selected or masked examples when values are necessary to understand a field.

Catalog retrieval

Search approved procedures, blocks, aliases and previous mappings before asking a general model to invent a new answer.

Confidence decomposition

Store which signals created a suggestion: name similarity, overlap, dictionary match, model judgement and previous approval.

Enterprise concerns

The boring parts decide whether this can be used.

Security

File classification, encryption, temporary storage, deletion policy, secrets, approved AI endpoints and dependency review.

Audit

Procedure version, block versions, user decisions, run ID, source fingerprints, validations, exceptions and output hashes.

Scale

Streaming or lazy scans, column pruning, Parquet intermediates, bounded samples and limits on expensive pairwise discovery.

Change impact

Dependency graph, consumer links, replacement chains and pinned versions make shared changes reviewable before rollout.
