Detail 03 / Architecture & libraries

Separate discovery from execution.

The architecture should allow experimental matching and AI assistance without making the execution path unpredictable. The safest split is simple: discovery proposes a procedure; the runtime executes an approved procedure.

OverviewApproachProcedure ModelArchitectureRoadmap

Logical layers

One engine, several replaceable parts.

Source adapters

Read Excel, CSV, Parquet and later enterprise sources. Convert them into a common tabular representation while keeping source metadata.

Profiler

Build structural fingerprints: schema, types, nulls, uniqueness, patterns, cardinality and safe samples.

Discovery engine

Generate candidate keys, mappings and source-role matches. Combine deterministic signals with optional semantic or AI signals.

Procedure editor / compiler

Turn approved choices into a valid procedure definition and then into a deterministic execution plan.

Execution engine

Apply joins, filters, conversions, derived fields, aggregations and exception routing without depending on an LLM.

Validation engine

Run structural, relational and business checks before and after transformations. Produce machine-readable evidence.

Registry and provenance

Version procedures, source contracts, mapping dictionaries, owners, approvals and run reports.

Interfaces

CLI first, then API and UI. Agents can become another client of the same procedure service instead of receiving a private execution path.

Candidate stack

Choose libraries by responsibility.

This is a working shortlist, not a dependency lock file. The project should keep adapters thin enough to replace a library when requirements change.

Polars

Strong candidate for the main Python dataframe runtime, especially for columnar operations and lazy execution. Useful when the procedure should compile into an optimized transformation plan.

DuckDB

Good embedded SQL engine for joins, aggregations, CSV/Parquet work and analytical steps. It also gives a future browser option through DuckDB-Wasm, with browser memory and threading limits to respect.

Apache Arrow / PyArrow

Useful common in-memory and interchange layer. Parquet is a good internal artifact format for larger intermediate data and test fixtures.

openpyxl

Python adapter when workbook-level XLSX details matter. Keep it at the boundary; the core procedure model should not depend on Excel cell objects.

SheetJS CE

Candidate for a future browser client that needs local spreadsheet reading or preview. It is a UI/input adapter, not the procedure engine.

RapidFuzz

Useful for field-name similarity and alias matching. Treat fuzzy text similarity as one mapping signal, never as proof of semantic equality.

Pandera

Good fit for code-centric dataframe schema checks close to the Python runtime. It can represent typed contracts and collect multiple validation errors.

Great Expectations

Consider when validation becomes a larger governed capability with reusable suites, persisted validation results and human-readable data-quality evidence.

Pydantic + JSON Schema

Use for the procedure and run-report contracts, API validation and migrations between spec versions. JSON Schema keeps the contract portable outside Python.

FastAPI

A reasonable service boundary later: procedures, discovery sessions, runs and reports become explicit API resources while the engine stays a normal Python package.

Start Python-first. Keep browser execution optional.

AI layer

Make semantic help a plug-in.

Metadata-only mode

Send column names, types, descriptions and statistics without row values. Useful when data sensitivity is high.

Masked sample mode

Use carefully selected or masked examples when values are necessary to understand a field.

Enterprise dictionary

Retrieve approved aliases, SAP field concepts, previous mappings and project vocabulary before asking a general model.

Confidence decomposition

Store which signals created a suggestion: name similarity, overlap, dictionary match, model judgement and previous approval.

Enterprise concerns

The boring parts decide whether this can be used.

Security

File classification, encryption, temporary storage, deletion policy, secrets, approved AI endpoints and dependency review.

Audit

Procedure version, user decisions, run ID, source fingerprints, validations, exceptions and output hashes.

Scale

Streaming or lazy scans, column pruning, Parquet intermediates, bounded samples and limits on expensive pairwise discovery.

Extensibility

Source adapter, transform operation, validation rule and semantic provider should be plugin boundaries rather than branches in one giant function.
