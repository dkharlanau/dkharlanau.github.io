Semantic layer

Give the same business thing one stable meaning.

Column names change across Excel files, SAP tables, APIs and projects. A semantic concept gives the framework a stable business identity behind those representations. It helps discovery, mapping, validation, search and reuse speak the same language.

OverviewCatalogSemantic ConceptsReference DataProcedure

Core idea

A concept is not just a list of aliases.

Material, MATNR and productId may point to the same business idea, but a useful registry also records how the identifier behaves, where it comes from and what assumptions are safe.

IDStable concept ID

Example: sap.material-id. Human labels may change; the concept ID should remain stable.

SEMMeaning

Short business definition, scope, owner, related domain and what the concept does not mean.

REPRepresentation

String or number behavior, expected length, leading-zero rules, locale, case behavior and safe comparison rules.

BINDSource bindings

Known fields such as SAP MATNR, Excel Material or API productId, with system and context.

RELRelationships

Broader, narrower, equivalent-in-scope, derived-from or related concepts.

RULESemantic rules

Known validations, canonical comparison behavior and warnings that procedures can reuse.

Important distinction

Same label does not guarantee same value space.

CaseMeaningFramework treatment
Same concept, different representation000000000000123456 and 123456 may represent the same material identifier.Use an approved representation or comparison rule.
Same label, different scope“Plant” may mean supplying plant, receiving plant or production plant.Use different concepts or explicit contextual bindings.
Same field, changed semanticsA source keeps the header but changes what values mean.Treat as semantic drift, not harmless schema compatibility.
Cross-system mappingTwo systems use different identifiers for the same business object.Use reference data or a governed mapping, not a fake equality rule.

Concept contract

Keep observable metadata and business meaning together.

{
  "id": "sap.material-id",
  "label": "Material ID",
  "domain": "material",
  "definition": "Identifier of a material or product master record in a declared source scope.",
  "valueKind": "identifier",
  "representation": {
    "logicalType": "string",
    "leadingZeros": "representation-sensitive",
    "caseSensitive": false
  },
  "bindings": [
    {"system": "SAP S/4HANA", "field": "MATNR", "context": "material master"},
    {"sourceFamily": "SAP export", "headerAlias": "Material"}
  ],
  "relations": [
    {"type": "related-to", "concept": "sap.material-description"}
  ]
}

How procedures use it

Concept references reduce duplicated reasoning.

Discovery

A new column can be matched against known aliases, value patterns and previous source bindings before semantic AI is asked.

Mapping

Two fields mapped to the same concept become stronger candidates, while different concepts warn against accidental joins.

Validation

Concept-level rules can suggest identifier checks, date semantics, allowed comparison behavior or required reference datasets.

Catalog search

Search for procedures that consume or produce sap.material-id, regardless of local header names.

Drift

A stable schema with changed concept evidence becomes semantic drift and can require review.

Agent context

An agent retrieves an approved meaning and known bindings instead of guessing business semantics from a column name.
