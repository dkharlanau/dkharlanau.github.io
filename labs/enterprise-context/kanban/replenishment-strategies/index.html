Kanban / 03

EMPTY is only a request.
The strategy decides what SAP does next.

The same demand-side signal can launch very different supply processes. A Lead should first identify the physical source, then choose the SAP replenishment object that represents it with the least unnecessary complexity.

Decision matrix

Start with the source, not with the transaction.

Each family can have several execution variants. The key question is what should exist after the EMPTY signal and what evidence should prove completion.

MAKE

In-house production

Use when the source is an internal production process. The replenishment object can be manual/no-document execution, a repetitive-manufacturing quantity, or a production order.

Completion evidence: produced quantity, backflush or goods receipt, and restored Kanban state.
BUY

External procurement

Use when a supplier refills the demand point. The signal can work with purchase orders, scheduling-agreement schedule lines, contracts, source lists, or related purchasing arrangements.

Completion evidence: purchasing reference, actual goods receipt, and restored Kanban state.
MOVE

Stock transfer

Use when material already exists in another plant or storage location and needs to be moved to the demand-side stock point.

Completion evidence: transfer object or reservation, material document, receiving stock, and restored Kanban state.

In-house production

Choose how much formal execution evidence you need.

The physical refill can be the same while the ERP representation is very different.

MANUAL

Card + cost collector

The EMPTY signal does not have to create a separate replenishment document. The production source sees the card or board, produces the container quantity, and later posts the required production/backflush activity.

Best fit: very repetitive internal loops where a separate order per container would add little control value.

REM

Run-schedule quantity

The signal can create a repetitive-manufacturing quantity. When the container is completed, backflush can post the finished quantity and component consumption against the repetitive process and cost collector.

Best fit: repetitive manufacturing with stable production versions and line-side supply.

ORDER

Production order

EMPTY can create a production order for the replenishment quantity. Depending on configuration, order release and output can be automated. Completion can be linked to backflush or handled with a separate goods receipt.

Best fit: when order-level execution, traceability, costing, or confirmation is required.

SEPARATE GR

Decouple goods receipt from status

In some designs the physical goods receipt is posted independently from the Kanban status progression. This helps when receiving and line-side status are separate operational steps.

Risk: FULL must not be interpreted as posted stock if the goods receipt is still missing.

External procurement

One supplier can support different replenishment documents.

The correct choice depends on the commercial relationship, expected frequency, and whether each Kanban signal should map to its own purchasing document.

PO

Purchase order

EMPTY can create a purchase order for the container quantity. The delivery date comes from purchasing and material master data, while the receiving destination comes from the Kanban/control-cycle design.

Use when each signal should create an explicit procurement document.
SA

Scheduling agreement

EMPTY can create a schedule line against an existing scheduling agreement. The relationship is not necessarily one container to one receipt: one delivery can cover several empty containers, depending on quantity and configuration.

Use for high-frequency supplier relationships where the agreement already owns the commercial frame.
CONTRACT

Contract release

A quantity or value contract can provide the outline agreement while each signal creates a release document against it.

Use when the commercial commitment exists before individual Kanban calls.
SOURCE

Source list

A source list can help determine the valid supplier or outline agreement when many control cycles use shared sourcing rules.

Keep the valid Kanban source unambiguous for the required period.
local_shipping

Direct-to-PSA design: if the supplier physically delivers to a line-side or staging point, make sure the purchasing destination, storage location, unloading point, and goods-receipt process describe the same route. A correct purchase order with the wrong operational destination still creates a bad Kanban loop.

Open procurement context arrow_forward

Goods receipt behavior

Do not fake FULL when the delivered quantity is different.

In a goods-receipt-driven design, posting the receipt can also set the container to FULL. The actual received quantity still matters for Inventory Management.

Full delivery

  • Receive the expected quantity.
  • Material document reflects the actual receipt.
  • Configured status action can restore the container to FULL.

Under-delivery

  • Post the real quantity in Inventory Management.
  • Do not use a status-only action to pretend the expected stock arrived.
  • Keep final-delivery and open-quantity logic consistent with the purchasing document.

Lead proof

  • Kanban status.
  • PO or schedule-line quantity.
  • Material document quantity.
  • Actual receiving stock.

Stock transfer

A pull signal can move existing stock instead of creating new supply.

The source may be another storage location or another plant. The design determines whether the transfer is direct or represented by a reservation or stock-transfer document.

DIRECT

Direct transfer posting

The signal is fulfilled by moving stock from the supplying storage location to the receiving location. The stock posting and the Kanban status change are closely coupled.

Use when: the physical route is simple and an additional transfer document adds little value.

RESERVATION

Transfer with reservation

EMPTY can create a planned transfer requirement or reservation. The later transfer posting consumes that intent and restores the demand-side quantity.

Use when: the source warehouse needs a clear planned issue before the movement.

TWO STEP

Stock transport flow

For longer or cross-plant movement, issue and receipt can be separate events. This makes stock-in-transit and receiving evidence visible.

Use when: the physical move cannot be represented as one immediate storage-location transfer.

CLASSIC

Movement references

Classic examples often use 311 for storage-location transfer and 351/101 for two-step stock transport scenarios.

Release boundary: validate the exact movement and document design in the target process; do not select movement types by memory alone.

Cost-center variants

Bulk consumption can sit outside normal component backflush.

Some line-side materials are consumed as overhead or bulk material rather than as a precise BOM component for each assembly. Kanban can still replenish them while the consumption is posted to a cost center.

Withdrawal to cost center

  • Material is available in local stock.
  • Consumption is charged to a cost center when the Kanban process reaches the configured point.
  • Classic systems often use movement 201 for cost-center goods issue.

Procurement to cost center

  • Material can be procured directly for consumption rather than held as normal warehouse stock.
  • Account assignment and the replenishment relationship must remain consistent.

Lead check

  • Is the material really bulk/overhead?
  • Should it be stock-managed?
  • Which cost center owns consumption?
  • Could normal BOM backflush be more transparent?
