SAP Procurement / Selected Customizing

Document type controls the document.
Field selection controls the fields.

In Purchasing, several configuration layers work together. A document type defines the business variant and allowed structure. Item categories define item behavior. Field-selection keys decide whether a field is hidden, display-only, required, or optional. EVO and EFB add user-specific defaults and function controls.

Start with the control model arrow_downward
account_tree

Lead rule: when a purchasing field or process behaves differently for two users or two document types, do not start by changing the screen. First identify the document category, document type, item category, transaction/activity, release status, and user parameters.

The same field can be influenced by several keys at the same time.

Mental model

Read the control stack from business document to user.

01

Document category

PR, RFQ, PO, contract, or scheduling agreement.

02

Document type

Number ranges, field-selection key, and process-specific behavior.

03

Item category

Controls item-level process behavior and must be allowed for the document type.

04

Field selection

Combines transaction, activity, document type, item category, EFB, and release status.

05

User controls

EVO proposes defaults. EFB restricts selected purchasing functions.

Document types

A document type is a control object, not only a label.

When defining a purchasing document type, start with the general parameters and then maintain the business-specific controls for that document category.

ControlWhat it determinesLead check
Item number intervalStep size between proposed item numbers.Formatting and usability control, not item process logic.
Number rangeInternal and, where allowed, external document numbering.At least one valid number range is needed for the document type.
Field-selection keyOne input into the final hidden/display/required/optional status of document fields.Do not diagnose the document-type key in isolation because other field-selection keys also apply.
Allowed item categoriesWhich purchasing item categories can be used with the document type.A new document type is incomplete if the required item categories are not assigned.
PR → external document linksWhich PR document-type and item-category combinations can be converted into which purchasing-document item categories.This is a conversion rule, not simple copy control by document name.

Important category-specific controls

DocumentImportant controlsWhat to remember
RFQGlobal percentage bid; time-dependent conditions.Time-dependent conditions allow validity periods and scales. The Fiori sourcing RFQ process has its own Customizing path.
Purchase RequisitionControl R; overall release; scenario-based workflow.Control R requires an outline agreement as follow-on instead of a standard PO. Overall release means the PR is released as a whole, not item by item.

warning

Copy trap: when a document type is copied, the partner schema assignment is not copied automatically. If partner functions are needed, assign the partner schema to the new document type.

Workflow trap: marking a document type for scenario-based workflow is not enough by itself. The relevant flexible-workflow scenario also has to be activated and configured.

PR conversion linkage

Document type and item category must form an allowed conversion path.

For example, if an NB purchase requisition is to become a subcontracting PO item, the relevant PR and PO item-category combinations must be maintained in Customizing.

IndicatorMeaningAssessment interpretation
NAA — No AccAssThe PO item may not contain account assignment even if the PR has one.The conversion mapping can deliberately change accounting behavior.
R/S — Contract Release / SA Schedule LineControls whether the combination can be used for release orders or scheduling-agreement schedule lines.Check it when the follow-on document is an outline-agreement execution step.
DialogControls whether SAP issues a warning when the combination is selected during conversion.A warning can be an intended control, not a technical error.

Customizing paths: Materials Management → Purchasing → Purchase Requisition / Purchase Order / Contract / Purchase Scheduling Agreement / RFQ → Define Document Types.

Field selection

The final field status is the combined result of several keys.

A field can be hidden, display-only, required, or optional. When several keys define different statuses, the more restrictive result wins.

1. Hide

Strongest result. If one relevant key hides the field, it is hidden.

2. Display

Stronger than required or optional. The user can see the value but cannot change it.

3. Required

Stronger than optional. The user must enter a value.

4. Optional

Weakest result. It remains optional only when no stronger key changes it.

Field-selection keys that can participate

Key sourceExamplesWhy it matters

fact_check

Classic example: Material Group can be optional in ME21N, AKTV, and NBF, but required in PT0F. The final result is required.

Diagnostic method: list every active field-selection key first. Do not change NBF only because the symptom is visible in an NB purchase order.

EVO and EFB

EVO changes defaults. EFB restricts selected purchasing functions.

ParameterMain purposeTypical controlsLead interpretation
EVOUser-specific defaults for buyers.InfoUpdate default, order acknowledgement requirement, fast processing, price adoption, source-determination defaults, delivery-date check.If two users receive different proposals but both are allowed to perform the action, check EVO and personal settings.
EFBUser-specific purchasing function authorization.Display/enter conditions, PO without material, adopt PR valuation price, allowed reference objects, manual source assignment.If one user cannot perform an action or cannot see/enter commercial fields, check EFB in addition to authorization roles and field selection.

EVO points worth remembering

Indicators

Can default InfoUpdate and order acknowledgement requirements for selected purchasing documents.

Fast processing

Can preselect template items and automatically adopt assigned PR items into the purchasing document.

Price adoption

Can suppress a default from the last PO. The manual-gross-price protection applies to the gross price condition only.

Source determination

Can default automatic source determination and check whether a source can meet the desired delivery date.

priority_high

MRP boundary: EVO source-determination settings such as Check Delivery Date are not used by the planning run. Do not use an EVO difference to explain an MRP sourcing result.

Customizing: EVO — Materials Management → Purchasing → Environment Data → Define Default Values for Buyers. EFB — Materials Management → Purchasing → Authorization Management → Define Function Authorizations for Buyers.

Info Record update

Separate “which info record is updated” from “which purchasing conditions are maintained”.

In ME21N, the Info Record Update indicator controls whether a purchasing info record is created or updated. Plant-level condition control influences which PIR level is selected for that update.

Condition controlInfoUpdate statusPIR level affected
Blank — conditions with or without plantCCreate purchasing-organization-level PIR if none exists; otherwise update an existing plant-specific or purchasing-organization-level PIR.
+ — plant-specific conditions onlyBCreate or update the plant-specific PIR.
− — no plant-specific conditionsACreate or update the purchasing-organization-level PIR.
warning

Assessment trap: InfoUpdate can create or update PIR data, but current SAP Learning explicitly notes that PO conditions themselves are not created or updated because InfoUpdate is selected. Do not describe InfoUpdate as a price-condition maintenance mechanism.

If an item has no material master record, the indicator is not proposed from the personal setting. It can still be set manually, which can create a material-group info record.

Customizing: Materials Management → Purchasing → Conditions → Define Condition Control at Plant Level.

Assessment

Five questions that expose whether the control model is understood.

Why is a PO field required although NBF says optional?

Another active key can be stricter. Check transaction, activity, item category, EFB, and release status. PT0F can make Material Group required.

Why can User A enter conditions but User B cannot?

Check EFB and field selection before changing document-type configuration.

Why does a new copied document type have missing partner behavior?

The partner schema assignment is not copied automatically. Assign it explicitly.

Why does source determination differ between ME51N and MRP?

EVO can influence manual defaults and delivery-date checks, but EVO is not considered by the planning run.

Why did InfoUpdate not change the supplier price condition?

Because InfoUpdate is about PIR creation/update. It is not a condition-maintenance mechanism.

record_voice_over

60-second answer: “I separate Purchasing Customizing into layers. The document type controls numbering, allowed structure, field-selection key, and special process behavior. Item categories must be assigned and PR-to-external-document combinations must be linked. Final field status comes from several keys, where hide is strongest, then display, required, and optional. EVO gives buyer defaults, while EFB restricts selected functions such as condition entry or manual source assignment. For an unexpected result, I reconstruct all active layers before changing configuration.”
