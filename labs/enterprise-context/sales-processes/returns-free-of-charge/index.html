After-sales / complaints / replacement

A complaint can reverse goods, reverse money, replace goods, or do more than one.

Returns and free-of-charge processes are easier when you separate the physical question from the financial question. Is the customer sending goods back? Are we refunding money? Are we shipping a replacement? These decisions create different document flows.

Free-of-Charge Delivery

C1000 receives a demo pack with no customer charge.

In classic on-premise standard, FD is a standard sales document type for free-of-charge delivery. Newer content also provides item designs that can create a zero-value or pro-forma billing result. The business rule is more important than the key: the goods leave stock, but the customer is not charged.

FOC sales order→ Availability check→ Outbound delivery→ Picking + PGI→ No-charge / pro-forma outcome
payments

Important: PGI still reduces inventory and can create a cost posting. “No customer price” is a commercial rule, not a promise that Finance sees nothing.

Free-of-Charge Subsequent Delivery

The replacement should keep a reference to the original problem.

A subsequent free-of-charge delivery is used when the customer should receive additional or replacement material without another charge. SAP complaints processing expects this branch to reference the earlier commercial document or return context.

Original order / return→ Subsequent FOC document→ Delivery→ PGI→ No new customer charge

Code caution: SAP standard document-type keys differ by release/content and customer copies. Current on-premise documentation lists SD as the standard subsequent-delivery type; many training or customer systems use copied keys. Learn the reference logic, not only the abbreviation.

Customer Return

Goods come back before the final disposition is known.

For a classic return, a return sales document such as RE creates the reverse logistics flow. The received material can go to returns blocked stock, inspection, unrestricted stock, scrap, or another follow-up activity depending on the returns design.

RE with reference→ Return delivery→ Goods receipt / inspection→ Disposition→ Credit or replacement

Movement examples: classic returns can use movement 651 into returns stock or 653 into unrestricted stock, depending on the configured return path. Advanced Returns Management adds a richer disposition tree, so do not treat one movement type as the definition of returns.

Troubleshooting

Separate physical recovery from financial correction.

SymptomFirst checks
Return delivery cannot be createdReference status, delivery block, return item relevance, shipping/receiving data, due date.
Returned stock lands in the wrong segmentSchedule-line category, movement type, return reason / follow-up activity, inspection setup.
Credit memo is blockedBilling block on the complaint document, approval status, reference quantity and billing due state.

Replacement loses complaint traceabilityCreate it with the intended reference and check copy control / document flow rather than creating an unrelated free order.
