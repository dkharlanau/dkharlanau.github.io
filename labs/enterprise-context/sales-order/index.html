Lead answer frame

Explain the first wrong decision in sixty seconds.

A Lead answer should not become a tour of configuration. Start with the business symptom, identify the control level, trace the decision, and finish with evidence that proves both the cause and the corrected business result.

1. Frame

  • State the expected business behavior.
  • Name the first wrong value, status, quantity, or date.
  • Place it at header, item, or schedule-line level.

2. Trace

  • Read the runtime inputs before opening configuration.
  • Follow input → determination → output → downstream consumer.
  • Stop at the first layer where expected and actual behavior diverge.

3. Prove

  • Separate root cause from downstream symptoms.
  • Explain the blast radius before changing shared configuration.
  • Define proof of cause and proof of business completion.

Example: if a schedule line behaves incorrectly, do not start by forcing the final schedule-line category. Check the item category and material-planning input first, because they are part of the determination context.

Dependency chain

The item is where several worlds meet.

Customer data, product data, sales configuration, logistics configuration, calendars, supply, and commercial rules meet inside one document.

Customer + Product → Plant Proposal → Plant → Shipping Point → Shipping Point
Departure + Destination + Shipping Policy → Route → Scheduling → Material Availability Date
Plant + Date + Quantity + Supply/Demand → Availability → Confirmed Qty / Date
Pricing Context + Condition Data → Pricing → Order Value → Credit Check → Continue / Block

These rails show reasoning dependencies. They intentionally hide technical branches that are not needed to understand the core idea.

Decision anatomy

Use the same six questions every time.

A repeated diagnostic shape makes the system easier to remember and makes comparisons between Pricing, ATP, Shipping, and other engines much easier.

  1. 01Question

    What business decision is SAP making?

  2. 02Inputs

    Which document, master-data, organization, or runtime values are read?

  3. 03Mechanism

    Lookup, procedure, condition technique, calculation, check, or search.

  4. 04Output

    Which value or status is produced?

  5. 05Next

    Which later decision consumes the result?

  6. 06Failure

    What should a consultant check before changing design?
