Sales BOM / Product Structure

A Sales BOM allows a sellable header product to explode into components in the sales document. The commercial behavior depends heavily on whether pricing and logistics are controlled at header or component level.

Mental model

Know what the object owns before tracing a document.

database

Scope: Header product, BOM usage, plant/validity, components and quantities.

Important data

BOM usage, header material, components, component quantities, alternative BOM, validity and plant context where relevant.

Configuration boundary

The BOM defines product structure. Item-category determination and pricing relevance are configuration, so the same structure can produce different sales behavior under different item-category settings.

Runtime use

How the data enters Order-to-Cash.

When the header is entered, BOM explosion creates subitems. Item category determination then controls whether the header or components are pricing- or delivery-relevant. Classic ERLA and LUMF-style designs represent different control patterns.

Troubleshooting

Start with the most specific evidence.

troubleshoot

Verify the BOM usage, validity and plant first. Then inspect the exploded item categories and their pricing/delivery relevance. If the structure is correct but pricing is wrong, troubleshoot item-category configuration rather than the BOM itself.

Assessment recall

A concise answer that still shows depth.

record_voice_over

A Sales BOM is product-structure master data. It tells SAP which components belong to the header; item categories decide where pricing and delivery control live.
