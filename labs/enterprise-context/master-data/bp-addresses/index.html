SAP Sales / Master Data / MD.SD.ADDRESS

Business Partner Address / Address Usage

A Business Partner can have several physical addresses. The important question is therefore not only which BP is used, but which address is valid for a specific role, date and business context. Address usage gives SAP a controlled way to select the correct address instead of treating every address as interchangeable.

Follow the runtime path arrow_downward

Object profile

01MD.SD.ADDRESSCatalogue ID
02relationship recordData class
Business Partner, address UUID, address usage, validity and partner/document context.

Mental model

Select the partner first; select the physical address second.

database

Scope: Business Partner, address UUID, address usage, validity and partner/document context.

Important data

Address UUID, address usage, validity dates, postal data, communication data and address-dependent customer information where supported.

Configuration boundary

Address determination is not the same as partner determination. Partner determination selects the business partner for a role; address logic selects which physical address of that partner is relevant.

Runtime use

One Business Partner can be correct while the document address is still wrong.

Partner determination resolves the Business Partner for a role. Address logic then resolves which valid physical address of that partner belongs to the document context. The selected address can be copied into Sales, delivery, billing, output, or integration payloads and can matter for execution and location-dependent processing.

01

Name the partner role

Start with the actual ship-to, bill-to, payer, or other partner in the document. Do not diagnose an address before confirming the correct Business Partner was selected.

02

Read address usage and validity

Check which address UUID is valid for the relevant usage and document date. Multiple addresses are expected; the question is which one qualifies.

03

Compare the document snapshot

Verify the address that was copied into the Sales document. A later master-data change does not automatically prove what the document originally contained.

04

Follow downstream consumers

Check whether delivery, billing, tax context, output, or an interface consumed the document address or performed its own determination.

Troubleshooting

Wrong partner and wrong address are different incidents.

troubleshoot

First prove that the document has the correct partner role. Then compare its stored address with the BP's valid address usages for the document date. If master data is correct but the document differs, inspect document-specific address changes, reference copying, or interface input. If the document is correct but a downstream payload is wrong, move the diagnosis to that consumer.

Assessment recall

Partner identity and physical address are two decisions.

record_voice_over

60-second answer: I treat partner identity and physical address as two separate decisions. Partner determination tells me which Business Partner fills a role; address usage and validity tell me which physical address of that partner is relevant. I compare the valid BP address with the address snapshot stored in the document, then follow that value into delivery, billing, output, tax context, or integrations. This avoids changing the partner relationship when only the address is wrong.
