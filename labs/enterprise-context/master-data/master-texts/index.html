Text Control

Text Control is a search-and-transfer engine. SAP decides which text is needed, where to find it, and how to move it into the sales document.

Transfer modes

Copy and reference are not the same thing.

ACopy

Independent snapshot. Later source changes do not update the target.

BReference

Target points to the source. Editing the target breaks the reference.

CDynamic read

Read from the template at runtime. No text or reference is stored.

blankNot defined

Initial state, normally when no access sequence is assigned.

sync_alt

Assessment trap: if a copied text does not change after the master text changed, that can be correct. A copy is a snapshot.

Access sequence

SAP searches sources in order and stops at the first successful hit.

An access can point to a preceding document, customer master, material context or standard text. Each step can also use its own language rule.

1Preceding sales document → 2Customer sales-area text → 3Standard text from SO10
Language options

All languages, fixed language, partner-function language or sales-organization language.

Standard text

Use text object TEXT with a suitable text ID to read a reusable SO10 text.

Multilingual content

One text type can hold several language versions. You do not need a new text type per language.

Mandatory texts

A text can also control document completeness.

The procedure can mark a text as mandatory or display it during copy. If required text is missing, SAP can flag the document as incomplete.

error

For the special hard-coded incompleteness procedures 50 and 51, maintenance is done through view V_TVUVF in SM31. SAP Note 385982 covers this behavior.

Private Edition / on-prem

Classic enhancement uses VOFM. Customer routines traditionally use the 50–99 namespace.

S/4HANA Cloud

Use BAdIs such as Copying Requirement in Text Determination and Data Transfer in Text Determination. Register the routine, map the enhancement ID, then assign it to the access.

code

Cloud BAdI-based routine numbers use the 3000000–3009999 range. In the classic approach, sample routine 91 shows how a dynamic SO10 text name can be built from the material.

Integration trap

IDoc text segments can change normal text determination.

hub

For IDocs such as ORDERS, ORDCHG and REQOTE, empty E1EDKT2 or E1EDPT2 text segments can suppress normal text determination. When EDI behaves differently from VA01, check the payload before changing customizing.

S/4HANA notes

Small details that are useful to remember.

TX08 Comments

Available in S/4HANA 2023 for sales-document header and item text procedures.

Central setup

VOTXN is the practical entry point. In newer IMG structures, the activity is consolidated as Set Up Text Determination.

Display on copy

The procedure can show copied text to the user for review and can also participate in the incompleteness check.

Assessment recall

One minute is enough if the model is clear.

Text Control in SAP SD determines which text type is needed, which sources SAP searches, and how the text is transferred. I start in VOTXN: procedure, access sequence, source and language. Then I check the transfer mode — copy, reference or dynamic read. Procedures are assigned by document context such as sales document type or item category. For custom behavior, a copying requirement decides whether text should flow, while a data-transfer routine can change the source. In classic systems this can use VOFM; in Cloud the equivalent is BAdI-based.
