Customer Sales Partner Functions

Sales documents rarely contain only one customer role. Sold-to, ship-to, bill-to and payer can be different Business Partners. Customer sales partner functions store the maintained relationships that allow SAP to propose those roles consistently for a sales area.

Object profile

02relationship recordData class
Customer, sales area, partner function and partner counter.

Mental model

Know what the object owns before tracing a document.

database

Scope: Customer, sales area, partner function and partner counter.

Important data

Partner function, assigned partner, sales area, partner counter for multiple relationships and relevant validity or relationship data.

Configuration boundary

The partner procedure is configuration; the partner assignment is master data. A required role can therefore fail either because configuration expects it or because no suitable master relationship exists.

Runtime use

How the data enters Order-to-Cash.

At document creation the partner-determination procedure defines the roles to be resolved. Master data then supplies the candidate partners. The resulting partner set affects shipping, billing, output recipients and sometimes credit context.

Troubleshooting

Start with the most specific evidence.

troubleshoot

Read the partner procedure and the actual partners on the document. Then verify the sales-area partner assignments of the sold-to or relevant source partner. Check manual changes only after master data has been validated.

Assessment recall

A concise answer that still shows depth.

record_voice_over

I separate the rule from the relationship: partner determination defines which roles are needed, while customer/BP partner functions provide the maintained partners for those roles.
