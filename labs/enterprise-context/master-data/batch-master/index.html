Batch Master: the identity of one real lot

A product master describes what a product should be. A batch master describes what one real production or procurement lot actually is: its batch number, dates, origin, status and measured characteristics.

That difference becomes important in food, chemicals, pharmaceuticals and other industries where two quantities of the same material can have different shelf life, potency, quality, origin or legal status.

Mental model

Three objects answer three different questions.

Product / Material Master

What should this product be?

It contains general product settings such as batch-management relevance, total shelf life, minimum remaining shelf life and target specification ranges.

Batch Master

What is this lot actually like?

It stores the identity and lot-specific data: batch number, production or expiration dates, supplier batch, origin, status and classification values.

Batch Search Strategy

Which lot should the process use?

It defines the selection criteria, sort rule, batch-split behavior and quantity proposal used during batch determination.

rule

Lead rule: a batch can be perfectly maintained and still not be selected. Master data says what the batch is. Determination logic decides whether it is a candidate. Availability and warehouse execution decide whether it can actually be consumed or shipped.

Core data

What belongs to the Batch Master?

The exact field set depends on the release and process, but the following groups are the ones worth remembering.

Identity and origin

Material, batch number, plant context when plant-level batches are used, supplier, supplier batch number, country or region of origin and descriptive text.

Dates and usability

Date of manufacture, shelf life expiration date or best-before date, availability date, last goods receipt date, next inspection date and certification dates where relevant.

Status and lifecycle

Restricted or unrestricted batch status when batch status management is active, deletion indicator and other lifecycle information.

Classification

Measured technical or business values such as potency, viscosity, color, grade, concentration, quality class, production line or other customer-specific attributes.

inventory_2

Do not confuse batch master with batch stock. The master record describes the lot. Stock records tell you how much of that batch is available in a plant or storage location and in which stock category it sits.

Architecture decision

Batch level defines what “unique batch number” means.

The batch level is a central Customizing decision. It must be agreed early because changing it after productive batch data and stock exist can become a conversion project rather than a small configuration change.

Batch level Unique key in business terms Batch class type Design consequence
Plant level Material + Plant + Batch 022 The same material and batch number can represent different batches in different plants.
Material level Material + Batch 023 The batch identity follows the material across plants.
Client level Batch number is unique across the client 023 The strongest uniqueness rule. It requires strict governance of number assignment.

Customizing is under Logistics - General → Batch Management → Specify Batch Level and Activate Status Management. Do not memorize a “best” level without context. Choose it from traceability, inter-plant flow, numbering and integration requirements.

Classification

Classification is where the batch becomes useful for selection.

Batch classification stores values that differ from lot to lot. It is also the bridge between the Batch Master and automatic batch determination.

User-defined characteristics

Create business characteristics such as Z_POTENCY, Z_GRADE or Z_COLOR when the property is not already represented by a standard batch field.

Reference / object characteristics

These read values from referenced application fields. They are useful when a value already exists in the batch master and should be reused in classification logic.

Standard LOBM_* characteristics

SAP provides batch-specific characteristics for common logic such as expiration date, status, delivery date, remaining shelf life, storage location and available quantity.

science

Important: not every characteristic used by a search strategy belongs in the batch class. Some dynamic standard characteristics, such as remaining shelf life, are calculated for determination and are used in the selection class rather than stored as normal batch values.

Product target vs. batch actual

A useful design is to keep the allowed or target range at material level and the real measured value at batch level. Example: the product allows potency from 95% to 105%; batch B240091 was measured at 99.4%. This makes the classification useful for quality checks, usability rules and customer-specific selection.

Implementation path

How I would configure batch management on a project.

The order matters. If you start with search strategies before the batch model is stable, you create logic around master data that can still change.

01

Decide the batch identity

Define the batch level, numbering concept and whether batch status management is required. Treat this as an architecture decision, not a transaction setting.

02

Activate the material

Set the material as batch-managed in the relevant material master views. Define shelf-life data where the business needs expiration checks.

03

Design classification

Create only characteristics that have a clear business use. Build the batch class and assign it to the material. Avoid a large “everything we might need” class.

04

Define creation and dates

Decide internal or external batch numbering, when batches may be created automatically, which dates come from the supplier or production, and which fields are mandatory.

05

Configure determination

Build condition tables, access sequences, strategy types, search procedures, selection classes and sort rules for the required MM, PP or SD process.

06

Maintain strategy records

Create the actual search-strategy master records with key combinations, selection values, sort rule, split controls and quantity proposal.

07

Test the complete chain

Test goods receipt, quality status, stock, sales or production determination, split behavior, warehouse execution and where-used traceability with realistic batches.

Creation

A batch is often created at the first goods receipt, but it does not have to be.

External procurement

At goods receipt, the user or interface provides a batch number or the system creates one. Supplier batch, production date and SLED can be captured from the inbound process.

Internal production

The finished-product batch is normally created or assigned around production and goods receipt. Component batches consumed by the order become part of the genealogy.

Manual pre-creation

Create the batch before stock exists when data must be prepared in advance, for example certification data, planned batch identity or controlled classification values.

For daily master-data work, SAP provides the Manage Batches app (F2462) to search, display, create and edit batches. Classic transactions such as MSC1N, MSC2N and MSC3N are still useful in many on-premise landscapes.

Shelf life

SLED is a process rule, not only a date field.

If total shelf life is maintained for the material and the date of manufacture is entered at goods receipt, SAP can calculate the shelf life expiration date. Minimum remaining shelf life can then be checked at goods receipt. Depending on configuration, a failed check can produce a warning or an error.

01

Material rule

Maintain total shelf life and, where required, minimum remaining shelf life in the product or material master.

02

Goods receipt

Enter production date or SLED. The system calculates or checks the date according to the configured rule.

03

Batch master

The final SLED becomes lot-specific master data and can also be exposed through standard batch characteristics.

04

Determination

Use remaining shelf life for selection and expiration date for sorting when the business wants FEFO-like behavior.

event

FEFO is not one checkbox. A good design combines shelf-life data, selection rules, sort sequence and the warehouse stock-removal logic. A batch can have the earliest expiration date and still be unusable because of status, stock category, customer requirements or warehouse constraints.

Batch determination

Read determination as a pipeline.

This sequence is one of the most useful models for both implementation and support.

01

Find the search procedure

The business transaction calls the relevant batch-determination procedure for SD, Inventory Management, Production or another application.

02

Find a valid strategy

SAP evaluates strategy types and adopts the first valid search strategy. Key combinations can include fields such as customer, material, plant, movement type or order type.

03

Select candidate batches

The selection class and characteristic values filter batches that match the required specification.

04

Check availability

Matching master data is not enough. The system checks whether usable quantity exists for the process.

05

Sort the result

The sort rule orders the surviving batches, for example by expiration date, batch characteristic or available quantity.

06

Propose quantity and split

If several batches are allowed, quantity proposal and split settings decide how the requirement is distributed.

Batch search strategy uses the condition technique. The configuration contains condition tables → access sequence → strategy type → search procedure → assignment to the business transaction. The maintained strategy record is the runtime master data that supplies selection and sorting rules.

Process Classic strategy maintenance Typical key fields
Inventory Management MBC1 / MBC2 / MBC3 Movement type, plant, material
Production / Process Orders COB1 / COB2 / COB3 Order type, plant, component material
Sales & Distribution VCH1 / VCH2 / VCH3 Customer, material, plant or sales-related keys depending on design

SD process

Sales can determine a batch in the order or in the delivery.

Sales-order determination

Use it when the batch is part of the commercial promise or customer specification. The order can already carry the selected batch or selection requirements.

Delivery determination

Use it when the real warehouse stock should drive the decision closer to picking. This is common when many batches can satisfy the same sales requirement.

Batch split

A delivery item can be fulfilled from several batches. The parent item represents the commercial demand; split subitems represent the physical lots that will be picked and issued.

A customer can also require specific batch properties. Example: Customer A accepts only grade A product with at least 60 days of remaining shelf life. That requirement belongs in the determination design, not as a manual warehouse instruction.

Integration

The same batch crosses MM, QM, PP, SD and EWM.

MM / Purchasing

Goods receipt creates or updates the lot, captures supplier batch and dates, creates batch stock and can check minimum remaining shelf life.

QM

Inspection results can provide the measured values that classify the batch. Quality decisions can also influence whether the stock or batch is usable in the next process.

PP / Process Manufacturing

Component batches are selected for production and the finished batch is created at receipt. The consumed component lots and produced lot form the basis of batch genealogy.

SD

Sales or delivery determination can select lots according to customer, material, plant, shelf life and specification rules. Batch split supports fulfillment from more than one lot.

EWM

In EWM scenarios, batch determination can run directly in EWM. S/4HANA can pass selection characteristics while EWM considers warehouse-specific stock and picking rules.

Integration APIs

The current Batch Master Record OData service is exposed as API_BATCH_SRV_0001 in communication scenario SAP_COM_0337 for supported S/4HANA Cloud integrations.

hub

Architecture boundary: decide which system owns batch selection. If EWM performs determination, changing only the S/4 search strategy may have no effect on warehouse picking.

Status and stock

“Blocked batch” can mean several different things.

Batch status

When batch status management is active, the lot can be unrestricted or restricted. The status can participate in determination through standard characteristic LOBM_ZUSTD.

Stock category

Quantity can sit in unrestricted-use, quality inspection, blocked or another stock category. This is inventory state, not the same thing as the batch status.

Availability

A batch can match classification and still have no usable quantity for the current document because stock is in another location, category, warehouse or is already committed.

Traceability

Batch management becomes valuable when something goes wrong.

For a complaint or recall, the useful question is not “does the batch exist?” but “where did it come from, what went into it, and where did it go?”

01

Supplier or source lot

Identify the received raw-material or externally procured batch and its supplier reference.

02

Production consumption

Trace which component batches were consumed by the production or process order.

03

Finished batch

Identify the produced lot, its inspection results, dates and classification.

04

Outbound delivery

Trace which batch and quantity were issued in each delivery.

05

Customer impact

Use the document chain to identify affected customers, quantities and dates for targeted recall or investigation.

The Batch Information Cockpit and batch where-used functions are the natural investigation tools. For support work, trace actual goods movements and documents; classification alone cannot prove that a lot was physically consumed or shipped.

Troubleshooting

When the “wrong batch” is selected, find the first stage where reality differs from expectation.

Symptom Check first Common root cause
No strategy found Business step, search procedure, strategy type and key combination The condition record does not match plant, customer, movement type, order type or material.
Expected batch is missing Selection class and actual characteristic values The batch does not satisfy one selection condition, remaining shelf life or status rule.
Correct batch exists but is not proposed Usable stock and availability Quantity is in the wrong stock category, storage context or is not available for the transaction.
Correct batches, wrong order Sort sequence Expiration date or another characteristic is missing from the sort rule or sorted in the wrong direction.
Correct batches, wrong split quantity Number of splits and quantity proposal The strategy limits the split or distributes quantity differently from the business expectation.
Works in S/4 but not in warehouse System ownership of determination EWM performs its own determination or stock removal and therefore uses another control layer.

Project lessons

Design choices that save problems later.

Do not overload classification

Every characteristic should have an owner and a use: selection, sorting, quality, compliance, analytics or integration. Otherwise it becomes expensive master data with no process value.

Separate source from calculated data

Decide which fields come from the supplier, production, QM or a calculation. Do not let several interfaces overwrite the same batch property without ownership rules.

Test bad batches, not only good ones

Create expired, restricted, low-stock and wrong-specification batches. A design is proven when SAP rejects the right candidates for the right reason.

Test cross-module ownership

Agree whether SD, EWM, PP or another step is responsible for the final batch selection. Otherwise teams can configure several competing solutions.

Assessment recall

A strong 60-second answer.

record_voice_over

Batch Master represents one real lot of a material. The material master defines the general product and rules such as batch relevance and shelf life; the batch stores lot-specific values such as dates, status, origin and classification. Batch determination is a separate condition-technique process: SAP finds a search strategy, filters batches by selection characteristics, checks availability, sorts the valid candidates and proposes quantities or batch splits. In an incident I therefore separate four layers: master data, determination rules, stock availability and execution in SD, PP or EWM.
