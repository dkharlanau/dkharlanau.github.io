Sales Item Proposal

An item proposal is a reusable shopping list for sales order entry. It is useful when a customer repeatedly orders the same set of products. Instead of entering each line manually, the user can call a proposal and copy selected items and quantities into the document.

Object profile

01MD.SD.ITEMPROPOSALCatalogue ID
02relationship recordData class
Proposal, sales area, products, proposed quantities and customer assignment where used.

Mental model

This is an entry shortcut, not a determination engine.

database

Scope: Proposal, sales area, products, proposed quantities and customer assignment where used.

Important data

Proposal identifier, products/materials, proposed quantities, units, sales area and customer assignment or usage context.

Configuration boundary

Item proposal data is not cross-selling and not a material determination rule. It is an explicit reusable list, whereas cross-selling recommends additional products and material determination substitutes a requested product.

Runtime use

The proposal helps create items; it does not continue to own them.

The proposal supports faster order or quotation entry by presenting a reusable set of products and proposed quantities. The user selects or copies the relevant lines into the document. After that, those lines behave as normal Sales items: item-category, pricing, ATP, delivery, and billing logic belong to their own mechanisms.

01

Open the right proposal

Confirm the proposal identifier, Sales context, and any customer assignment used to make the list available.

02

Read the maintained list

Check which products, quantities, and units the proposal actually contains instead of diagnosing the finished order first.

03

Copy selected lines

The proposal supplies entry data. The user can select the relevant items; the proposal does not independently create a complete Sales transaction.

04

Hand ownership to the order

Once copied, troubleshoot price, confirmation, delivery, or billing from the normal Sales-order mechanisms. The proposal no longer explains those downstream results.

Troubleshooting

Separate a missing proposal item from a bad Sales item.

troubleshoot

If a product is missing before copying, inspect the proposal itself, its assignment, and Sales context. If the product was copied correctly but later has the wrong price, date, confirmation, or delivery behavior, leave Item Proposal and diagnose the resulting Sales item. That ownership boundary prevents an entry aid from becoming a false root cause.

Assessment recall

Contrast entry assistance with determination.

record_voice_over

60-second answer: Item Proposal is reusable Sales entry assistance: a maintained set of products and proposed quantities that a user can copy into an order or quotation. It is not material substitution and it is not cross-selling recommendation logic. I use it to explain how the line entered the document; after the copy, normal item-category, pricing, ATP, delivery, and billing mechanisms own the result.
