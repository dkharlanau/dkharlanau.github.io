Material Determination Record

Material determination lets Sales replace a requested product with another product according to maintained substitution rules. Typical uses include successor products, customer-specific replacements or controlled substitutions during product transitions.

Follow the runtime path arrow_downward

Object profile

01MD.SD.MATDETCatalogue ID
02condition recordData class
Condition type/key, requested material, validity and substitution reason.

Mental model

The record owns the substitution mapping; configuration owns how SAP finds and applies it.

database

Scope: Condition type/key, requested material, validity and substitution reason.

Important data

Requested material, substitute material, condition key, validity dates, substitution reason and context fields configured in the condition table.

Configuration boundary

The record says which substitution is valid. The determination procedure, condition type, access sequence and substitution-reason behavior are configuration.

Runtime use

The requested product can change before later Sales decisions use it.

When a material is entered, the material-determination procedure can search for a valid substitution and then apply the configured substitution behavior. The important distinction is between the maintained mapping and the engine around it: procedure, condition type, access sequence, condition table, and substitution reason decide how the record becomes document behavior.

01

Start from the requested product

Capture the material the user or interface actually entered, together with the document date and Sales context.

02

Follow the search

Identify the active determination procedure, condition type, access sequence, and runtime key. This tells you which condition records SAP can reach.

03

Prove the valid mapping

Check the requested material, substitute, validity, and other key fields in the record that was found—or prove that no valid record exists.

04

Read the substitution behavior

Check the substitution reason and resulting item structure. The same mapping can have different business effects when configuration changes how the alternative is introduced.

05

Continue downstream

Only after the substitution is clear should you explain later item-category, pricing, ATP, delivery, or billing effects for the resulting Sales item.

Troubleshooting

Find whether the failure is search, record, or substitution behavior.

troubleshoot

Start with the originally requested material, document date, and Sales context. If SAP never reaches the expected key, the problem is in procedure or access logic. If the key is reached but no valid mapping is found, inspect the condition record. If the alternative is found but the document structure is unexpected, inspect the substitution reason and its configured behavior. ATP or item-category effects come later in the chain.

Assessment recall

Separate the mapping from the determination engine.

record_voice_over

60-second answer: Material determination is Sales substitution based on condition technique. The record contains the requested-to-alternative product mapping for a defined key and validity. Configuration decides how SAP searches for that record and how the substitution reason changes the sales item. I diagnose it in three layers: did SAP execute the expected access, did it find a valid mapping, and did the substitution behavior create the expected item structure? Only then do I move downstream to pricing, ATP, delivery, or billing.
