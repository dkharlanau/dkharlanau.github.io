SAP Sales / Master Data / MD.SD.PRODHIER

Product Hierarchy and Sales Groupings

Product hierarchy gives Sales a commercial classification that is broader than a single material. It is useful when pricing, reporting or segmentation should operate on groups of products rather than maintaining rules for every material number.

Follow the runtime path arrow_downward

01MD.SD.PRODHIERCatalogue ID
02relationship recordData class
Product, sales area and hierarchy/grouping value.

Mental model

Know what the object owns before tracing a document.

database

Scope: Product, sales area and hierarchy/grouping value.

Important data

Product hierarchy, product group-related sales fields, sales organization/distribution channel scope and version or validity where the implementation uses dedicated hierarchy structures.

Configuration boundary

A product hierarchy value is master data. The decision to include it in pricing access sequences, analytics models or selection logic belongs to configuration/design.

Runtime use

How the data enters Order-to-Cash.

Pricing can use product hierarchy values in condition tables. Reporting and commercial segmentation can aggregate sales by the same structure. The value therefore becomes important whenever a rule or analysis is intentionally defined above material level.

Troubleshooting

Start with the most specific evidence.

troubleshoot

Check the hierarchy value on the product sales view used by the order. Then inspect the condition table or reporting logic that is supposed to consume it. Do not assume the hierarchy has runtime effect merely because it is populated.

Assessment recall

A concise answer that still shows depth.

record_voice_over

Product Hierarchy is a commercial grouping of products. I verify the maintained hierarchy value and then the pricing or reporting logic that consumes that value.
