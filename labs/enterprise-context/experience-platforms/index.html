Experience platforms / the layer people actually enter

The business systems can be correct.
The workplace can still be broken.

A user may need S/4HANA, Ariba, SuccessFactors, IBP, custom BTP apps, and third-party tools in one working day. An experience platform gives that user a simpler front door without pretending that all business logic lives in one system.

Experience layer: how people find, enter, and move through work.

System of record: where the business object, transaction rules, and authoritative state live.

Why a separate class

This problem is not owned by SD, MM, HR, or Finance.

Experience platforms sit across business domains. They become relevant when the user journey crosses products, systems, and process boundaries. The architectural question changes from “Which module owns the transaction?” to “How does the user reach the right work without learning the whole landscape?”

ENTRY Central entry point

One role-based place to start work across several applications.

The goal is faster access and clearer navigation, not a second copy of every backend.

WORK Digital workplace

Applications can sit next to information, collaboration, and business context.

This is broader than an application launcher when the workplace itself must support teams and knowledge.

TASK Task aggregation

A single inbox can reduce task hunting across systems.

The task aggregator does not automatically become the workflow engine that created the task.

AI / MOBILE Alternative entry channels

Mobile and conversational entry can shorten the path to a business action.

They still depend on identity, authorization, source applications, and reliable business services.

Adjacent components

Similar user surfaces can own very different responsibilities.

Do not choose by product name. Start with the job that the component must own.

01

SAP Fiori launchpad

Think: application launchpad and shell. It gives role-based access to Fiori applications and shell services. Work Zone can sit above several product launchpads as a cross-solution entry point.

02

SAP Start

Think: predefined SAP cloud entry point. It is useful when supported SAP cloud products need a ready central home. Work Zone is more configurable and can cover SAP, custom, third-party, cloud, and on-premise content.

03

SAP Task Center

Think: aggregated tasks. It provides a common task inbox; Work Zone can provide the place where that inbox is reached.

04

Joule and mobile entry

Think: another way to reach work. Conversational or native-mobile entry can improve access, but it does not move transaction ownership away from source applications.

Lead diagnostic

When somebody asks for “one portal”, do not start with the portal.

First find the real fragmentation. The request may hide several different architecture problems.
