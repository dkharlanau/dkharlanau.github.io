Enterprise Context / Decision Cards

Good SAP answers explain
the choice and its boundary.

These cards are not product summaries. Each one starts with a real design question, makes the default choice explicit, and shows what would make me change that choice.

01ContextWhat problem exists?
02ChoiceWhat is my default?

Decision reasoning is separated from vendor facts.
rule

Working rule: a Lead answer should not stop at “it depends”. State the default, name the decision drivers, show the failure owner, and explain the condition that changes the design.

Knowledge chain: each decision should sit between a domain and an applied scenario, with reviewed evidence behind factual claims: Domain → Decision → Scenario → Evidence.

Publication state: this decision layer is intentionally noindex while the cards pass the same source, sidecar, and publication checks as the reviewed Enterprise Context pages.

Reusable answer frame

Context → drivers → default → exception → recovery.

  1. 01Context

    State the business outcome and the boundary that needs an owner.

  2. 02Drivers

    Name the few variables that actually change the decision.

  3. 03Default

    Give a preferred design instead of hiding behind a list of options.

  4. 04Exception

    Explain what would make the default wrong.

  5. 05Recovery

    Close with failure ownership, reconciliation, and proof of business completion.

school

Assessment use: pick a card, defend the default for two minutes, then challenge it with a different volume, legal structure, recovery requirement, or risk boundary.
